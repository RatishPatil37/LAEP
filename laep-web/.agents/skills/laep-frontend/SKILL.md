
# LAEP Frontend Skill

## Purpose

Build a high-quality frontend for LAEP without falling into generic AI-generated website patterns.

## Design Language

LAEP should communicate:

"Scientific planetary intelligence."

Use:

- strong editorial typography
- dark astronomical backgrounds
- restrained cyan/ice accents
- restrained warm solar accents
- precise spacing
- subtle technical metadata
- large visual compositions
- real scientific imagery/data where available
- purposeful motion

Avoid:

- excessive rounded cards
- excessive pills
- gradient-everything
- glowing borders everywhere
- excessive blur
- unnecessary glass panels
- generic bento grids
- decorative metrics
- meaningless badges

## Layout

Prefer:

- large visual hero compositions
- asymmetric layouts where appropriate
- strong hierarchy
- generous whitespace
- layered information
- full-width scientific visualizations
- immersive exploration sections

Do not make every section look like a collection of cards.

## Components

Build reusable components for:

- navigation
- buttons
- panels
- scientific metadata
- data legends
- layer controls
- location/crater information
- charts
- tooltips
- loading states
- error states
- modal/inspector interfaces

Avoid creating duplicate components with slightly different styling.

## Motion

Motion should communicate:

- navigation
- spatial movement
- state changes
- scientific transitions
- interaction feedback

Do not animate everything.

Prefer subtle, smooth motion over constant movement.

## Responsive Design

Design desktop and mobile intentionally.

Do not simply shrink the desktop interface.

For 3D scenes, provide sensible mobile performance/fallback behavior.

## Code Quality

Prefer:

- small components
- clear naming
- reusable tokens
- predictable state
- minimal dependency additions
- separation between visual components and application logic

Avoid giant components containing the entire page.
